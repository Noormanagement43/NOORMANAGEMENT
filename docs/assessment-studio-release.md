# Assessment studio — 11 November 2026

Assignments now contains Weekly Test, Monthly Test and configured school exams. Principals save category-specific marks, question count, formats, difficulty and time limit under Subjects & Exams → Online Test Settings. Sections inherit class rules unless overridden. Weekly tests use Saturdays; monthly/exams accept their scheduled date.

Teachers can choose active classes and sections within their own school for tests, written assignments and today's homework. Homeroom attendance and My Class retain their existing scope. Up to eight syllabus images are compressed locally and sent to the authenticated backend. Generation returns editable questions, private answer keys, explanations and a syllabus/quality report. Teacher approval is required before publication.

Student papers use their school's logo/name and own class/section, with selectable MCQ/blank options, one-word and short answers, concept visuals and private profile-photo URLs. The paper opens in a dedicated full-screen surface on desktop and phones, with no permanent app or question sidebars. All questions are visible in one scrollable paper. Menu/left-edge swipe opens a drawer with question and school navigation. Drafts save to the authenticated backend and remain editable until final submission or expiry. Final submission is immutable.

Objective questions use deterministic approved-key scoring. Written answers enter a private durable grading queue; the authenticated grading service validates model output and atomically saves one category/subject/date result. The worker retries queued jobs every minute, with leases, bounded attempts and teacher fallback. Answer keys and worker credentials are not exposed to students. Existing legacy quizzes keep their existing approval behaviour.

Validation: 255 JavaScript tests, 17 backend tests, DOM integration through authoring/approval/student submission/results, and rollback-only live SQL integration for school/class boundaries, principal rules, immutable submission, queue leases, score validation and idempotent result creation. Deployed grading endpoint rejects anonymous requests with HTTP 401; scheduled worker is active. No permanent test students or quiz records were created. Mobile layout is CSS/DOM-verified; no authenticated real-device visual test was available in this environment.

The live countdown uses a server-persisted deadline and survives reloads. The server rejects late edits, uses the last securely saved answers at expiry and finalizes expired sessions every minute even if the browser closes. Local drafts additionally protect edits during a brief connection failure. Model availability/quota can delay written marks; answers remain saved and the teacher can review submissions. Teacher review of generated questions/keys remains necessary for academic accuracy.

## Full-screen exam and regeneration update

The review form now has its own change-description box and Generate Again button. Each successful regeneration replaces the draft with a new numbered version, using the prior draft and the same class/category settings. Teacher approval is required for the final version. Approved picture scenes (sunrise, water, plant, reading, watering, farmer and animal) render from a fixed safe illustration library; arbitrary model HTML/SVG is not accepted.

The generation schema no longer expands bounded arrays into large provider constraints; exact question count and marks remain validated in backend code. Live provider checks returned 30 questions and 30 keys, a multi-image draft, and a revised draft. Two additional backend tests cover schema complexity/error privacy. Live rollback SQL verifies deadline persistence, late-edit rejection, automatic expiry submission and no duplicate results. The unsubmitted Al Iqra English paper shown as Monthly was corrected to Weekly on Saturday 14 November, preserving its approved questions/key.
